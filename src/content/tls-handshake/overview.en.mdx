## What TLS protects

When you open an `https://` page, TLS protects the connection in three ways:

- **Confidentiality** — nobody on the network can read the data.
- **Integrity** — nobody can change it without being noticed.
- **Authentication** — the client can be sure it is talking to the real server, thanks to a **certificate**.

## The handshake in one round trip

1. **ClientHello** — the client lists what it supports and already sends its half of the key exchange (**key share**).
2. **ServerHello** — the server picks the parameters and sends its key share. Both sides now compute the same secret and derive the **handshake keys**. Everything after this is encrypted.
3. **EncryptedExtensions, Certificate, CertificateVerify, Finished** — the server sends its certificates, proves it holds the private key, and confirms the handshake.
4. **Finished** — the client checks everything and confirms too. Both sides switch to the **application keys**.

## Certificates and the chain of trust

The server’s certificate is signed by an **intermediate CA**, whose certificate is signed by a **root CA**. The client trusts a root only if it is already in its **trust store**. It checks each certificate’s signature and validity period, and that the server certificate is issued for the name it wanted to reach (the **SAN**). If any check fails, the client sends an **alert** and stops.

## What to look for in the walkthrough

- Where the diagram switches from **not encrypted** to **encrypted**.

## Try it yourself

`openssl s_client` runs a TLS handshake and prints what was agreed. Use OpenSSL (for example Homebrew’s `openssl@3`): the `openssl` that comes with macOS (`/usr/bin/openssl`) is LibreSSL, which has neither `-brief` nor `-verify_hostname`.

```sh
openssl s_client -connect example.com:443 -servername example.com -brief < /dev/null
```

Trimmed output (OpenSSL 3.6.1 on macOS 26, 2026-09-29):

```
CONNECTION ESTABLISHED
Protocol version: TLSv1.3
Ciphersuite: TLS_AES_256_GCM_SHA384
Peer certificate: CN=example.com
Verification: OK
Negotiated TLS1.3 group: X25519MLKEM768
```

- **Protocol version** and **Ciphersuite** are what the ServerHello chose. **Verification: OK** means the server’s certificate chain was checked against the trust store. `-servername` sends the name in SNI, but s_client checks that the certificate matches it only if you also add `-verify_hostname example.com`.
- **group** is the key-exchange group used for the key shares. Here it is X25519MLKEM768, a hybrid that combines X25519 with the post-quantum ML-KEM; the walkthrough uses plain X25519. Run it without `-brief` and with `-showcerts` to print the whole chain.
- `curl -v https://example.com/` also shows the TLS version and the certificate. In Wireshark, the filter `tls.handshake` shows only the ClientHello and ServerHello in readable form: in TLS 1.3 the rest of the handshake is already encrypted.
