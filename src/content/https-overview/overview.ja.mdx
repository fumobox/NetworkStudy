## ページを開くと何が起きるか

ブラウザーに `https://www.example.com/` と入れると、ページが表示されるまでに 4 つのプロトコルが順に働く。それぞれにこのサイトのテーマがあり、このページではそれを 1 本のステップ実行につなげている。

1. **DNS**: ブラウザーは `www.example.com` の IP アドレスをリゾルバーに尋ねる。→ [DNS の名前解決](/themes/dns-resolution)
2. **TCP**: ブラウザーはそのアドレスの 443 番ポートに、3 ウェイハンドシェイクで接続する。→ [TCP 3 ウェイハンドシェイク](/themes/tcp-handshake)
3. **TLS**: その接続の上で、ブラウザーとサーバーが鍵を合わせ、ブラウザーはサーバーの証明書チェーンを確かめる。最後に、要求 `GET /` をもう暗号化して送る。→ [TLS 1.3 のハンドシェイクと証明書](/themes/tls-handshake)
4. **HTTP**: サーバーは、同じハンドシェイクで導いたアプリケーション用の鍵で暗号化してページを返す。

## 往復の回数が積み重なる

ページの最初の 1 バイトが届くまでに、ブラウザーは何回かの往復を待つ。名前解決（答えがキャッシュになければ）、TCP で 1 往復、TLS 1.3 で 1 往復、そして要求と応答そのもので 1 往復。DNS の答えをキャッシュしたり、接続を使い回したりするとページが速く開くのはこのため。

## ステップ実行で見てほしいところ

- 図の帯（点線と名前）で、それぞれのメッセージが 4 つの段階のどれに当たるかがわかる。
- 状態パネルでは、ブラウザーが各段階の結果（調べたアドレス、TCP の状態、TLS の状態）を持っている。
- 鍵のマークが付いたメッセージが暗号化されている。ServerHello まで（名前解決を含む）は、ネットワークの途中で誰でも見られる。

このページでは短くするため、「もしも…」のオプションは省いている。それぞれのテーマで試してほしい。

## 手元で試す

`curl -v` は、ページを開くまでの各段階を表示する。

```sh
curl -v -o /dev/null https://example.com/
```

出力の一部（macOS 26 の curl 8.7.1、2026-09-29）:

```
* Host example.com:443 was resolved.
*   Trying [2606:4700:10::6814:179a]:443...
* Connected to example.com (2606:4700:10::6814:179a) port 443
* ALPN: curl offers h2,http/1.1
* SSL connection using TLSv1.3 / AEAD-CHACHA20-POLY1305-SHA256 / [blank] / UNDEF
* ALPN: server accepted h2
> GET / HTTP/2
< HTTP/2 200
```

- 行の順はステップ実行と同じ。名前を解決し（DNS）、TCP の接続を作り、TLS のハンドシェイクで TLS 1.3 と、ALPN で HTTP/2 に合意し、暗号化した接続で要求と応答が行き来する。
- 往復がどう積み重なるかは、curl に時間を出させるとわかる（始めからの秒数）。

```sh
curl -o /dev/null -s -w 'dns %{time_namelookup}  tcp %{time_connect}  tls %{time_appconnect}  first byte %{time_starttransfer}\n' https://example.com/
```

```
dns 0.001950  tcp 0.034158  tls 0.072933  first byte 0.131620
```

- ここでは名前はキャッシュから来た（2 ms）。TCP のハンドシェイクに約 1 往復（32 ms）、TLS にもう約 1 往復（39 ms）、要求の後、応答の最初のバイトまでに、さらに約 1 往復とサーバーの処理時間（59 ms）かかった。Linux の curl も同じオプションを使える。
