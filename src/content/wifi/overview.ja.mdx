## 線のないネットワーク

Wi-Fi は IEEE 802.11 の規格群。ふつうの**インフラストラクチャモード**では、端末（**STA**、ステーション）が**アクセスポイント**（AP）につながる。AP とその STA の集まりが **BSS**（basic service set）。BSS には名前の **SSID** と、識別子の **BSSID**（AP の MAC アドレス）がある。AP は有線 LAN へのブリッジでもあり、802.11 はこの有線の側を**ディストリビューションシステム**（DS）と呼ぶ。1 つの DS に同じ SSID の AP が複数あれば、ESS（extended service set）になる。

STA が IP パケットを送れるようになるまでに、3 つの段階がある。ネットワークの発見、認証とアソシエーション、そして鍵を決める 4 ウェイハンドシェイク。

## ネットワークを見つける

- **パッシブスキャン**: AP はおよそ 100 TU（1 TU = 1,024 µs なので 102.4 ms）ごとに **Beacon** をブロードキャストする。中身は SSID、BSSID、使える速度、そして受け入れる暗号と鍵の管理方式を並べた **RSN 要素**（RSNE）。WPA2-Personal なら CCMP-128 と事前共有鍵。
- **アクティブスキャン**: STA が **Probe Request** をブロードキャストする。SSID はワイルドカード（長さ 0）のことが多い。AP はユニキャストの **Probe Response** で答える。

多くの機器は、スキャンのときやネットワークごとに、ランダムでローカルに管理された MAC アドレスを使う。MAC アドレスで追跡されないようにするため。

## 認証とアソシエーション

名前にだまされやすいが、802.11 の **Open System 認証** はセキュリティではない。STA が名乗り、AP は誰でも受け入れる。歴史的な理由で残っている手順で、古い WEP はここで共有鍵を使う方式を行っていた。**アソシエーション**によって、STA は BSS のメンバーになる。AP は STA を記録し、**アソシエーション ID**（AID）を割り当てる。

802.11 はこれを 4 つの状態で表す。

| 状態 | 意味 |
|---|---|
| State 1 | 認証もアソシエーションもしていない |
| State 2 | 認証したが、アソシエーションしていない |
| State 3 | アソシエーションしたが、鍵はまだ決まっていない（データフレームは EAPOL だけ通れる） |
| State 4 | アソシエーションし、鍵も決まった（または鍵がいらない）。データを送れる |

## 4 ウェイハンドシェイク

WPA2-Personal では、両者は **PMK**（ペアワイズマスター鍵）をすでに共有している。PMK はパスフレーズから作る。HMAC-SHA1 を使う PBKDF2 で、ソルトは SSID、4,096 回、256 ビット（RFC 8018）。ハンドシェイクは PMK を送らず、両者が PMK を知っていることを証明する。

1. AP が乱数の **ANonce** を送る。まだ鍵がなく計算できないので、このメッセージには MIC がない。
2. STA は **SNonce** を選び、PMK、両者の MAC アドレス、両者のノンスから **PTK**（ペアワイズ一時鍵）を導く。PTK は **KCK**（MIC 用）、**KEK**（鍵を包む用）、**TK**（データの暗号化用）に分ける。STA は SNonce に、KCK で計算した **MIC** を付けて送る。AP も同じ PTK を導いて MIC を確かめる。一致すれば、STA が PMK を知っていることの証明になる。
3. AP は自分の MIC を送り、AP も PMK を知っていることを示す。あわせて、ブロードキャストとマルチキャストに使う **GTK**（グループ一時鍵）も送る。フレームは暗号化されていないが、Key Data のフィールドは暗号化されている。GTK は KEK で包まれている。Install のビットは、PTK を入れるよう STA に伝える。
4. STA が確認を返す。そのあと STA は PTK と GTK を入れ、AP も PTK を入れる。802.1X のポートが開く。実際には、次はたいてい DHCP。

また AP は、メッセージ 2 の RSNE が Association Request のものと同じことを、STA は、メッセージ 3 の RSNE が Beacon のものと同じことを確かめる。攻撃者がセキュリティの方式を格下げしようとしても、これで気づける。2017 年の **KRACK** 攻撃では、多くのクライアントがメッセージ 3 を再送されると鍵を入れ直し、ノンスを最初に戻してしまうことが示された。これはパッチで直された。

## WPA2-Personal の弱点と WPA3

ハンドシェイクのメッセージ 1 と 2 を記録すれば、誰でもオフラインでパスフレーズを試せる。推測ごとに PMK と PTK を計算して MIC を確かめる。AP がするのとまったく同じ手順で、これが**オフラインの辞書攻撃**。短いパスフレーズはこれに耐えられない。また、SSID がソルトなので、よくある SSID のネットワークどうしは、あらかじめ計算した表を使い回されてしまう。

**WPA3-Personal** は、事前共有鍵の代わりに **SAE** を使う。パスワードで認証する鍵交換で、Authentication のフレームの中で行う。やり取りを記録してもオフラインの推測の役に立たない。また、あとでパスワードを知った者でも、以前に記録した通信は復号できない（前方秘匿性）。WPA2-Personal では、パスフレーズを知っていてハンドシェイクを記録した者なら PTK を計算できる。WPA3 では **PMF**（管理フレームの保護、802.11w）も必須で、Deauthentication などのフレームを偽造されないようにする。

## データフレームとアドレス

データフレームには最大 4 つのアドレスのフィールドがある。その意味は、Frame Control の 2 つのビット **ToDS** と **FromDS** で決まる。Address 1 は常にこの 1 区間の受信者、Address 2 は常に送信者。

| ToDS / FromDS | 場面 | Address 1 | Address 2 | Address 3 |
|---|---|---|---|---|
| 0 / 0 | IBSS の中 | DA | SA | BSSID |
| 1 / 0 | STA から AP | BSSID | SA | DA |
| 0 / 1 | AP から STA | DA | BSSID | SA |

両方のビットが 1 ならアドレスは 4 つで、メッシュやブリッジのリンクで使う。このページでは扱わない。同じ BSS の STA どうしでも、通信はふつう AP を通り、2 つのフレームになる。AP は送信者の TK で復号し、受信者の TK で暗号化し直す。

## 電波を分け合う: CSMA/CA

チャネル上のすべての STA が 1 つの媒体を共有する。そして無線は、送っている最中には衝突を聞き取れない。衝突は受信者のところで起き、送信者にはその受信者の周りの電波が聞こえないこともある。そこで Wi-Fi は、初期の Ethernet の衝突検出（CSMA/CD）ではなく、**衝突回避**（CSMA/CA）を使う。送れたかどうかは **Ack** でしかわからない。

- **キャリアセンス**: 送る前に聞く。物理的なキャリアセンスは無線の CCA。仮想キャリアセンスは **NAV** で、聞こえたフレームの Duration のフィールドから設定する。
- 媒体が **DIFS** のあいだ空いていたら、0 から CW までのランダムな**バックオフ**のスロットを数える。途中で媒体が使われたら、数えるのを止める。
- 受信者は **SIFS** のあとに Ack を返す。SIFS は DIFS より短いので、あいだに誰も割り込めない。グループアドレス宛てのフレームには Ack がない。
- Ack が来なければ、CW を 2 倍にし（15 → 31 → 63 … 最大 1,023）、**Retry** のビットを立てて同じシーケンス番号で送り直す。受信者は重複を捨てられるが、Ack は返す。

5 GHz の OFDM（802.11a と、後の PHY の non-HT の速度）での時間:

| | 時間 |
|---|---|
| スロット | 9 µs |
| SIFS | 16 µs |
| DIFS = SIFS + 2 スロット（DCF） | 34 µs |
| ベストエフォートの AIFS = SIFS + 3 スロット（EDCA） | 43 µs |
| 24 Mb/s の Ack | 28 µs |

今の 802.11n/ac/ax の機器は **EDCA** を使い、通信の種類ごとに AIFS と CW を変える（ふつうはベストエフォート）。このページでは、より単純な DCF と DIFS を使う。

## 隠れ端末と RTS/CTS

AP を挟んで反対側にいる 2 台の STA は、どちらも AP の電波は届くが、互いの電波は届かないことがある。するとキャリアセンスが働かない。どちらも媒体が空いていると思い、AP でフレームが重なって、両方とも失われる。**RTS/CTS** を使うと、STA はまず短い RTS（送信の要求）を送る。AP が CTS（送信の許可）で答える。CTS を聞いた STA はすべて、CTS の Duration から NAV を設定し、送信者の電波が聞こえなくても、やり取りが終わるまで黙る。フレームが 2 つ増えるので、ふつうは RTS threshold を超える大きなフレームにだけ使う。

## アドホック（IBSS）

AP がなくても、STA どうしで **IBSS**（independent BSS）を作れる。アソシエーションも DS もなく、データは STA から STA へ直接送る（ToDS = FromDS = 0）。IBSS を始めた STA は、ランダムな BSSID を選ぶ。グループのビットは 0、ローカルに管理されたビットは 1。Beacon は、すべての STA が役目を分け合って送る。ビーコンの時刻ごとに各 STA がランダムな時間を待ち、最初に送った STA の勝ち。アドホックモードは今ではあまり使われない。同じ役目は、1 台が AP（グループオーナー）になる Wi-Fi Direct や、802.11s のメッシュネットワークが担う。

## ウォークスルーで見るところ

- Beacon の Capability のフィールド（ESS か IBSS か）と RSNE。
- ノート PC の 802.11 の状態（1 → 2 → 3 → 4）と 802.1X のポート。
- 4 つの EAPOL-Key のメッセージの Key Information、Key Replay Counter、Key MIC のフィールドと、ノート PC の鍵の表。
- 区間ごとのデータフレームの ToDS / FromDS のビットと 3 つのアドレス。
- Duration のフィールドと、各 STA の「送信の順番待ち」の状態。
- 「もしも…」の選択肢:
  - パスフレーズの誤り: メッセージ 2 が捨てられる。
  - Ack の消失: フレームが再送され、AP が重複を捨てる。
  - 隠れ端末: RTS/CTS を使う場合と使わない場合。
  - アドホックモード。

## 手元で試す

```sh
system_profiler SPAirPortDataType
```

今のネットワークについての出力の一部（macOS 26、2026-09-29。macOS はネットワークの名前を隠す）。

```
PHY Mode: 802.11ax
Channel: 6 (2GHz, 20MHz)
Security: WPA2 Personal
Signal / Noise: -46 dBm / -88 dBm
Transmit Rate: 229
```

- **PHY Mode** の 802.11ax は Wi-Fi 6。**Channel** の 6 は 2.4 GHz の帯で、幅は 20 MHz。**Security** の WPA2 Personal は、鍵がパスフレーズから、ウォークスルーの 4 ウェイハンドシェイクでできたこと。
- **Signal / Noise** は dBm。その差（ここでは 42 dB）が、リンクの速さをおおむね決める。**Transmit Rate** は今の速さ（Mb/s）。
- Linux では、`iw dev wlan0 link` がつながっている AP、周波数、信号の強さを表示する。Wireshark では、表示フィルター `eapol` で 4 ウェイハンドシェイクが見えるが、モニターモードで 802.11 のフレームをキャプチャーしたときだけ。ふつうのキャプチャーでは、通信は Ethernet に見える。

## このページについて

- 5 GHz の 1 つのチャネルで、non-HT の OFDM を 24 Mb/s で使い、DCF で送る。QoS のヘッダー、パワーセーブ、フラグメンテーション、アグリゲーションはない。
- 管理フレームと EAPOL のフレームにも Ack が返るが、データの区間でだけ描く。
- ノンスは値を示さず、MIC は大きさだけ示す。シーケンス番号とパケット番号は例の値。
- 有線の側（DHCP、ルーター）は描かない。アドホックのネットワークは暗号化のないオープンなもの。
- MAC アドレスは説明用の範囲（RFC 9542）のもの。ただし IBSS の BSSID は、乱数の例の値。

参加したあと、ノート PC は [DHCP](/themes/dhcp) でアドレスをもらい、[ARP](/themes/arp) で次のホップの MAC アドレスを調べる。AP の有線の側へのブリッジは、[スイッチ](/themes/switching) と同じように働く。Wi-Fi が層のどこにあるかは [OSI 参照モデル](/themes/osi-model) で見られる。
