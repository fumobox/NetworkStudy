## リンクごとに最大の大きさがある

リンクが運べる IP のパケットには、大きさの上限がある。これが **MTU**（Maximum Transmission Unit）で、Ethernet では 1500 バイト。家庭の光回線や DSL でよく使う PPPoE では、Ethernet のフレームの中に 8 バイトのヘッダー（PPPoE と PPP）が加わるので、MTU は **1492** しかない。経路全体での最小の MTU が**パス MTU**。

TCP の **MSS** は SYN のセグメントで知らせ、ふつうはそれぞれが自分のリンクから決める（1500 − 40 = 1460。IP のヘッダー 20 バイトと TCP のヘッダー 20 バイト）。MSS は、途中のリンクのことは何も表さない。

## パス MTU 探索

**パス MTU 探索**では、送信側はどのパケットにも **DF**（Don’t Fragment）のフラグを立てる。次のリンクが小さくてパケットを転送できないルーターは、パケットを捨て、ICMP の **Destination Unreachable、code 4**（Fragmentation Needed）を返す。このメッセージには**次のリンクの MTU**（Next-Hop MTU）と、捨てたパケットの先頭が入っているので、送信側はどの TCP の接続のパケットかがわかる。

送信側はその宛先のパス MTU を小さい値で記録し、TCP は同じデータを小さなセグメントで送り直す（1492 − 40 = 1452 バイト）。10 分ほどたつと、送信側はまた大きい値を試すことがある。

## ブラックホール

ファイアウォールが ICMP を**すべて**捨てていると、Fragmentation Needed は届かない。ハンドシェイクのような小さなパケットは通るが、満杯の大きさのパケットはどれも消え、再送も捨てられる。接続はできるのに止まってしまう。これが**パス MTU のブラックホール**。

対策は、ICMP の type 3 code 4 を通す、ルーターが SYN の MSS を書き換える（**MSS clamping**）、ホストが ICMP に頼らず自分で経路を試す（**PLPMTUD**、RFC 4821 / RFC 8899）のいずれか。

## フラグメント化

DF が立っていなければ、ルーターは代わりにパケットを**フラグメント**に分割してよい。どのフラグメントにも IP のヘッダーが付き、同じ **Identification**、8 バイト単位の **Fragment offset** を持ち、最後以外には **MF**（More Fragments）のフラグが立つ。組み立て直すのは宛先だけ。

フラグメント化はルーターの負担になり、フラグメントが 1 つでも失われるとパケット全体が失われるので、今の TCP はパス MTU 探索で避ける。IPv6 のルーターは分割せず、代わりに ICMPv6 の **Packet Too Big** を返す（RFC 8201）。IPv6 のリンクは、どれも少なくとも 1280 バイトを運べなければならない。

## ステップ実行で見てほしいところ

- ルーターが捨てる **DF** の立ったパケット、ICMP の **Next-Hop MTU**、PC のパス MTU と MSS が下がること。
- 「もしも…」のオプションで、ファイアウォールが ICMP を遮る場合（**ブラックホール**）と、**DF を立てず**に送る場合（ルーターが分割する）。

## 手元で試す

`ping -D` は Don’t Fragment のビットを立て、`-s` はデータの大きさを決める。1472 バイトのデータに、ICMP のヘッダー 8 バイトと IPv4 のヘッダー 20 バイトを足すと、1500 バイトのパケットになる。

```sh
ping -c 1 -D -s 1472 example.com
ping -c 1 -D -s 1473 example.com
```

出力の一部（macOS 26、2026-09-29）:

```
$ ping -c 1 -D -s 1472 example.com
1 packets transmitted, 1 packets received, 0.0% packet loss
$ ping -c 1 -D -s 1473 example.com
1 packets transmitted, 0 packets received, 100.0% packet loss
```

- 1500 バイトのパケットは通る。1501 バイトのものは、このコンピューター自身のリンク（MTU 1500）にさえ収まらず、DF が立っているので分割もできないため、応答は返ってこない。PPPoE の回線（1492）のように小さいリンクのある経路なら、上限はもっと低く、ルーターが ICMP の Fragmentation Needed で答えることがある。
- Linux では、同じ試しは `ping -M do -s 1472 example.com`。`tracepath example.com` は、パス MTU をホップごとに表示する。Wireshark では、表示フィルター `icmp.type == 3 && icmp.code == 4` で Fragmentation Needed のメッセージが見える。macOS は 1501 バイトのパケットを何も表示せずに捨てる（`netstat -s -p ip` の「datagrams that can't be fragmented」が増える）。Linux は代わりに「message too long」と表示する。
