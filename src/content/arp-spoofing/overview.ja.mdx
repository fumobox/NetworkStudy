## ARP は誰でも信じる

[ARP](/themes/arp) は、LAN の IP アドレスを MAC アドレスに変える。ホストどうしが互いを信頼するネットワークのために作られ、誰がパケットを送ったかを確かめる手段を持たない。さらに RFC 826 は、受け取ったすべての ARP のパケットから学ぶようホストに求める。送信元の IP アドレスがもうキャッシュにあれば、その MAC アドレスをパケットのものに書き換える。これは要求か応答かを見る前に起き、応答が自分の送った要求への答えかどうかは誰も確かめない。

そのため、「192.168.1.1 は 00:00:5e:00:53:42」という偽の応答 1 つで、PC はゲートウェイ宛てのフレームを、同じ LAN の別のホストに送るようになる。これが **ARP スプーフィング**（ARP キャッシュポイズニング）。LAN の内側からしかできない。ARP はルーターを越えないから。

## スイッチには見分けられない

[スイッチ](/themes/switching)は、Ethernet のアドレスでフレームを転送する。偽の応答は、自分の送信元についてはうそをつかない。Ethernet の送信元のアドレスも、送信元の MAC アドレス（SHA）も、攻撃者の本物の MAC アドレス。うそは送信元の IP アドレス（SPA）だけ。スイッチの MAC アドレステーブルは正しいままで、スイッチはほかのフレームと同じように届ける。その後、PC A のゲートウェイ宛てのフレームは攻撃者の MAC アドレス宛てになり、スイッチはそれを正しく攻撃者に届ける。

## 中間者。1 つの向きずつ

攻撃者はパケットを本当のゲートウェイに渡すので、何も壊れず、誰も気づかない。これで攻撃者は**中間者**（MITM）になる。

- 暗号化されていないもの（ふつうの DNS、ふつうの HTTP など）はすべて読め、書き換えられる。
- TLS なら中身は読めず書き換えられないが、PC A がどのアドレスと、いつ通信しているかは見える。

ゲートウェイのキャッシュは変わっていないので、インターネットからの答えは PC A に直接届く。両方の向きを見るには、攻撃者はゲートウェイにも、PC A のアドレスを名乗る偽の応答を送る。

攻撃者は応答を、1 台の相手へのユニキャストで送る。RFC 5227 §2.4 は、自分の IP アドレスを別の MAC アドレスで名乗るパケットを見たときにホストがすることを決めている。それは衝突で、既定のルーターのように変わらないアドレスが要るホストは、自分のアドレスをもう一度 Announcement で知らせて守ってよい。ブロードキャストはゲートウェイにも届き、この守りを始めさせうる。PC A へのユニキャストの応答は、決して届かない。

攻撃者は、うそを繰り返し続ける必要もある。キャッシュの行は期限が来ると確かめ直され、ゲートウェイからの本当の ARP のパケットが 1 つ届けば、PC A の行は直る。監視の道具が探すのは、この食い違う ARP のパケットの絶え間ない流れ。

## OS が足すもの

RFC 826 は基本の動きを決める。OS は独自の規則を足し、細部は OS ごとに違う。

- Linux（`arp_accept`。既定は 0）は、頼んでいない ARP で新しい行を作らない。しかし行がすでにあれば、`arp_accept` によらず、どの ARP のパケットでもその行を書き換える。
- PC にはゲートウェイの行がほぼいつもあるので、新しい行についての規則では、この攻撃は止まらない。

## 守り 1: DHCP スヌーピングと Dynamic ARP Inspection

Cisco の Catalyst などのスイッチは、ARP を自分で確かめられる。これらの機能は IETF や IEEE の標準ではない。ここでの名前は Cisco のもので、ほかのメーカーも別の名前で同じような機能を持つ。

- **DHCP スヌーピング**は**束縛表**を作る。ポートは、**信頼するポート**（DHCP サーバーや上流へのポート）と、**信頼しないポート**（ホストのポート）に分ける。サーバーの DHCPACK が信頼するポートを通ると、スイッチは、どの IP アドレスをどの MAC アドレスに、どのポートで、どれだけの期間渡したかを記録する。信頼しないポートに届いたサーバーのメッセージは捨てるので、偽の DHCP サーバーも止まる。
- **Dynamic ARP Inspection**（DAI）は、信頼しないポートのすべての ARP の要求と応答を横取りする。転送する前に、送信元の組（SPA と SHA）を束縛表で確かめる。表にない組は捨てて記録する。信頼するポートの ARP は確かめない。だからゲートウェイ自身には束縛が要らない。
- **静的なアドレスのホスト**（プリンター、サーバー）には束縛がないので、DAI はそのホスト自身の ARP を捨てる。管理者はこうしたホストを **ARP ACL** に書き、DAI は束縛表より先に ACL を見る。組を拒否する ACL の行は、合う束縛があっても優先される。
- Cisco のスイッチは、信頼しないポートの ARP を既定で毎秒 15 パケットに制限し、あふれたポートを止める。ほかのフィールド（Ethernet の送信元と SHA、Ethernet の宛先と THA、正しくない IP アドレス）も確かめられる。これらの数と選択肢は Cisco のもので、版によって変わる。

DAI は攻撃を見分けるのではない。送信元を信じる理由のある ARP のパケットだけを通し、その理由は DHCP から来る。

## 守り 2: 静的な ARP エントリー

管理者は、ゲートウェイの MAC アドレスを、ホストのキャッシュに**静的なエントリー**として書ける。ARP はそれを書き換えない。これは OS の機能で、RFC 826 にはない。守りは狭い。

- 守れるのは、そのホストのその 1 行だけ。ゲートウェイのキャッシュはまだだませる（逆の向き）。
- ネットワークカードを取り替えたら、すべての行を手で直す必要がある。
- 大事な数台より多くには広げられない。

## 正当な Gratuitous ARP

頼んでいない ARP のパケットがすべて攻撃なのではない。ホストは、新しいアドレスを ARP Announcement（RFC 5227 §2.3）で知らせる。送信元と対象の IP アドレスがどちらも自分のものの要求。VRRP（RFC 9568）で組んだルーターが切り替わると、新しくアクティブになったルーターが、仮想ルーターの MAC アドレスで Gratuitous ARP を送る。MAC アドレスは変わらず、主にスイッチの MAC アドレステーブルを新しくする。パケットを見ても、正直かどうかはわからない。DAI のもとで決め手になるのは、送信元の組に束縛があるかどうか。

## 標準はあるか

IETF の同じ考え方は **SAVI**（Source Address Validation Improvement）。RFC 7039 が枠組みを説明し、RFC 7513（SAVI for DHCP）は同じように DHCP から束縛を作り、信頼するポートのサーバーの応答からだけ記録する（§6）。さらに、送信元の IP アドレスが届いたポートに束縛されていない ARP のパケットと、対象の IP アドレスが束縛されていない ARP の応答を捨てる（§8.2）。そのため、このページの偽の応答も止まる。違いは細部にある。SAVI の束縛は、IP アドレスと MAC アドレスの組ではなくポート（binding anchor）に結びつき、SAVI はデータのパケットの送信元のアドレスもすべて確かめる。SAVI は仕様で、スイッチが持つのは DAI のようなメーカーの機能。IPv6 には、この攻撃と守りの IPv6 版（近隣探索のなりすまし、RA Guard、SEND）があるが、このページでは扱わない。

答えのもう半分は、上の層の暗号化。TLS（と [HSTS](/themes/hsts)）があれば、ARP がだまされても、中間者は中身を読めず、書き換えられない。

## ウォークスルーで見るところ

- **PC A** の ARP キャッシュ（Type の列は dynamic か static）、インターネットへのフレームの宛先、最後の ARP のパケットでしたこと。
- **スイッチ**の MAC アドレステーブル、信頼するポート、DHCP スヌーピングの束縛表、ARP ACL、フレームごとにしたこと。
- 偽の応答のフィールド。SHA と Eth Src は攻撃者のもの、SPA はゲートウェイのもの。どの選択肢でも同じパケットで、変わるのはネットワークだけ。
- 「もしも…」の選択肢:
  - 攻撃と、奪われるのが片方の向きだけであること。
  - DAI。DHCPACK からの束縛、信頼するポートからのゲートウェイの応答、捨てられる偽の応答。
  - ARP ACL に書くまで DAI に止められる、静的な IP アドレスのホスト。
  - 静的な ARP エントリー。

## 手元で試す

どのコマンドも状態を読むだけ。キャッシュを変えたり、ARP を送ったりするものはない。

```sh
arp -a -n
```

- macOS は ARP キャッシュを表示する（出力の例は [ARP](/themes/arp) のテーマを参照）。静的なエントリー（と、コンピューター自身のアドレスの行）には `permanent` が付く。Linux では `ip neigh` が同じキャッシュを表示し、静的なエントリーは `PERMANENT`。
- キャッシュで 2 つの IP アドレスが同じ MAC アドレスを持つのは、害のないこともある（アドレスをいくつも持つルーター）が、だまされたキャッシュもそう見える。
- Linux では、`sysctl net.ipv4.conf.all.arp_accept` が上で説明した設定を表示する。既定は `0`。
- Wireshark では、表示フィルター `arp.duplicate-address-detected` で、別の MAC アドレスとともにすでに見た IP アドレスを名乗る ARP のパケットが見える。エキスパート情報に、前に使われたフレームが示される。`arp.isgratuitous` で Gratuitous ARP が見える。

## このページについて

- スイッチは 1 台、VLAN は 1 つ、レーンは 4 本。ゲートウェイは DHCP サーバーを兼ねる。
- 攻撃では、だますのは PC A だけ。逆の向きは説明だけで、描かない。
- DHCP の DISCOVER、OFFER、REQUEST、ARP の再送とキャッシュのタイマーは描かない。攻撃者はパケットをそのまま渡し、TTL は描かない。
- DAI の追加の検査、レート制限、記録は説明だけで、描かない。
- 攻撃のやり方は、わざと書かない。このページの主題は、なぜ成り立つかと、どう止めるか。
