## DHCP なしで LAN につながる

IPv6 のホストは自分で設定できる。ルーターは LAN のプレフィックスを知らせるだけで、ホストは自分でアドレスを作り、誰も使っていないか確かめ、**近隣探索**（Neighbor Discovery）で隣の機器を見つける。近隣探索は ICMPv6 のメッセージの集まりで、ARP と、DHCP の多くの役目を置き換える。

| メッセージ | 宛先 | 役目 |
|---|---|---|
| Router Solicitation（RS） | `ff02::2`（すべてのルーター） | 「ルーターはいる？」 |
| Router Advertisement（RA） | `ff02::1`（すべてのノード） | プレフィックス、デフォルトルーター、DNS サーバー |
| Neighbor Solicitation（NS） | 要請ノードマルチキャストのグループ | 「このアドレスは誰？」「誰か使っている？」 |
| Neighbor Advertisement（NA） | 尋ねた機器、またはすべてのノード | 「私です。MAC アドレスはこれ」 |

## 手順

1. **リンクローカルアドレス**: ホストは `fe80::/64` と自分のインターフェース ID を組み合わせる。ルーターは要らず、LAN の中だけで使える。
2. **重複アドレス検出**（DAD）: 未指定アドレス `::` から「誰か使っている？」と尋ね終わるまで、アドレスは *tentative*（仮）。1 秒以内に答えがなければ *preferred* になる。
3. **RS と RA**: ホストがルーターを探し、ルーターがプレフィックスを答える。A フラグが **SLAAC**（ステートレスアドレス自動設定）を許し、M と O のフラグが DHCPv6 が要るかどうかを示す。
4. **グローバルアドレス**: プレフィックスとインターフェース ID。これも DAD で確かめる。
5. **アドレス解決**: LAN の中で送るとき、ホストは NS で相手の MAC アドレスを尋ね、答えを**近隣キャッシュ**に覚える。

## ブロードキャストの代わりにマルチキャスト

IPv6 にはブロードキャストがない。NS は相手の**要請ノードマルチキャストアドレス**（`ff02::1:ff` と下位 24 ビット）に送り、このグループに入る機器はわずか。ほかの機器は NIC がフレームを捨てるので、システムのほかの部分をわずらわせない。

## ステップ実行で見てほしいところ

- PC のアドレスの表。`tentative` → `preferred`、あとからグローバルアドレスが加わる。
- それぞれのマルチキャストを、どの機器が受け取り、どの機器が捨てるか。
- 近隣キャッシュ。RA で `STALE`、PC 2 については `INCOMPLETE` → `REACHABLE`。
- 「もしも…」のオプションで、アドレスの重複と、ルーターのない LAN。

## このページについて

アドレスを追いやすいよう、インターフェース ID は MAC アドレスから作った（EUI-64）。今のほとんどの OS は、代わりにランダムなインターフェース ID を使う（RFC 7217、RFC 8981）。MLD（参加したグループをホストが知らせるしくみ）、スイッチの MLD スヌーピング、DAD と RS の前のランダムな待ち、定期的な RA、DHCPv6、近隣キャッシュの DELAY と PROBE の状態は扱わない。PC 2 が自分のアドレスを設定するところは描いていない。アドレスの書き方と種類は、IPv6 アドレスのテーマも参照。
