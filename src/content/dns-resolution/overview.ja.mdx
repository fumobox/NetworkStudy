## DNS がすること

コンピューターは IP アドレスで相手に接続するが、人は `www.example.com` のような名前を使う。DNS（Domain Name System）は名前をアドレスに変える仕組み。全部の対応表を持っているサーバーはなく、名前の空間は**ゾーン**に分けられ、ゾーンごとに担当の**権威サーバー**が管理している。

## 登場する役者

- **スタブリゾルバー** — PC の中の小さなクライアント。質問を 1 つ送り、最終的な答えを待つ。
- **フルサービスリゾルバー** — ふつうは ISP や会社、公開 DNS サービスが運用している。実際の仕事を引き受け、**キャッシュ**を持つ。
- **ルート、TLD、example.com のサーバー** — どれも自分のゾーンの権威サーバー。ルートは `com.` のようなトップレベルドメインの担当を知っていて、`com.` のサーバーは `example.com.` の担当を知っていて、`example.com.` のサーバーが答えを知っている。

## 再帰問い合わせと反復問い合わせ

スタブは**再帰**問い合わせ（RD フラグ）を送る。「答えを見つけてきてほしい」という依頼。リゾルバーは**反復**問い合わせを送る。各サーバーは答えを返すか、答えにより近いサーバーを**紹介**（委任）する（NS レコードと、必要ならそのアドレスの **glue**）。

## キャッシュと TTL

レコードにはそれぞれ **TTL**（生存時間）が付いている。リゾルバーはレコードを TTL が切れるまで覚えているので、次の名前解決では途中を飛ばしたり、どこにも聞かずに答えたりできる。「その名前は存在しない」（NXDOMAIN）という答えも、しばらくキャッシュされる。

## ステップ実行で見てほしいところ

- 各メッセージの **Flags**: 再帰問い合わせの RD、権威の答えの AA、委任やキャッシュからの答えに AA が付かないこと。
- 委任や答えを受け取るたびに増えていく、リゾルバーの**キャッシュ**。
- 「もしも…」のオプションで、キャッシュがあると経路がどう短くなるか、NXDOMAIN・CNAME・応答しないサーバーがどう見えるか。

このページでは、キャッシュの表に合わせてレコードを `NAME TYPE RDATA TTL` の順に書いている。`dig` などのツールでは `NAME TTL CLASS TYPE RDATA` の順に表示される。
