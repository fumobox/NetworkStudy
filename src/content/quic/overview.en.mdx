## Why QUIC

HTTP/2 over TCP has two costs: setting up a connection takes a TCP handshake plus a TLS handshake (two round trips before the first request), and one lost packet stalls every stream. **QUIC** is a transport protocol that runs over UDP and fixes both. **HTTP/3** is HTTP carried over QUIC.

## One round trip, with TLS built in

QUIC has no separate TLS layer: the TLS 1.3 messages travel in QUIC’s own `CRYPTO` frames. After one round trip, the connection exists *and* the keys are ready, so the browser sends its request together with its `Finished`.

Packets are protected at different **encryption levels** as the handshake goes on:

| Packet | Keys | Carries |
|---|---|---|
| `Initial` | derived from the connection ID, so anyone can compute them | ClientHello, ServerHello |
| `Handshake` | from the TLS key exchange | the rest of the TLS handshake |
| `0-RTT` | from a session ticket of an earlier visit | early requests |
| `1-RTT` | application keys | HTTP/3 requests and responses |

Several packets of different levels can share one UDP datagram. Packet numbers are counted in three separate **packet number spaces**: Initial, Handshake, and application data (shared by 0-RTT and 1-RTT). Within a space, a packet number is never reused.

## 0-RTT

If the browser connected before and kept a session ticket, it can send requests in its very first datagram (**0-RTT**). The server may accept them and answer right away, or reject them; then the browser sends them again once the handshake is done. An attacker can record 0-RTT data and send it again (a replay), so only requests that are safe to repeat should use it.

## Streams and loss

Each HTTP/3 request uses its own QUIC **stream**, and QUIC delivers each stream separately. A lost packet stalls only the streams whose data it carried. QUIC declares a packet lost when packets sent after it are acknowledged (in the walkthrough, one numbered 3 higher). When no acknowledgment arrives at all, a probe timeout (PTO) makes it send again. Either way it resends the *data* in a new packet with a new number.

## What to look for in the walkthrough

- The label of each packet: its type, its packet number and the frames inside (the full list is in the Frames field of the packet details).
- The **Packet numbers sent** table: three separate spaces, and the Initial and Handshake spaces being discarded.
- In the “What if…” options: 0-RTT accepted or rejected, a lost first datagram (PTO), and a lost packet of stream 0 (stream 4 is not held back).

## About this page

One message is drawn as one QUIC packet; the description says when packets share a datagram. Retry, version negotiation, header protection, connection migration, key updates, congestion control, the server’s acknowledgment of the Handshake packet, and HTTP/3’s control streams and QPACK are left out. Browsers learn that a server supports HTTP/3 from an `Alt-Svc` header or a DNS record, which is not shown. Packet sizes are examples.
