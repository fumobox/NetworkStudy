## ICMP の役目

IP はパケットを届けるだけで、問題を知らせない。IP と一緒に使う報告や確認を運ぶのが **ICMP**（Internet Control Message Protocol）。ICMP のメッセージにはどれも **type** と **code** がある。

| type / code | 名前 | いつ |
|---|---|---|
| 8 / 0 | Echo Request | ping が「いますか？」と尋ねる |
| 0 / 0 | Echo Reply | Echo Request への答え |
| 11 / 0 | Time Exceeded | TTL が 0 になったので、ルーターがパケットを捨てた |
| 3 / 1 | Destination Unreachable（host unreachable） | 最後のルーターがホストに届けられなかった |
| 3 / 3 | Destination Unreachable（port unreachable） | その UDP のポートで誰も待ち受けていない |

## ping と traceroute

- **ping** は Echo Request を送り、Echo Reply を待つ。答えがあればホストに届く。答えの TTL から、いくつのルーターを通ったかの見当がつく。
- **traceroute** は、ルーターが 1 ずつ減らす **TTL** を使う。TTL 1 のプローブは最初のルーターで、TTL 2 は 2 つ目のルーターで尽きる。各ルーターが自分のアドレスから Time Exceeded で答えるので、traceroute はホップを並べられる。

Windows の `tracert` は ICMP の Echo をプローブにし、Linux の `traceroute` は既定で 33434 番以降のポートへの UDP を送る（宛先の Port Unreachable で終わる）。通常のパケット（ping の Echo Request など）の TTL は、Windows が 128、Linux が 64 から始まる。

## ステップ実行で見てほしいところ

- **TTL** の列。ルーターを通るたびに 1 ずつ減る。
- ICMP のエラーの送信元アドレス。サーバーではなく、エラーを送ったルーターのアドレスになる。
- 「もしも…」のオプションで、サーバーに届かない場合（Destination Unreachable）、答えが返らない場合（ping では応答のロス、traceroute では 2 ホップ目の `*`）、Port Unreachable で終わる UDP のプローブ。

## 手元で試す

```sh
ping -c 3 example.com
traceroute -n -q 1 -m 12 example.com
```

出力の一部（macOS 26、2026-09-29）。家庭のルーターと、ISP の最初のいくつかのホップは、例のアドレスに置き換えた。

```
PING example.com (104.20.23.154): 56 data bytes
64 bytes from 104.20.23.154: icmp_seq=0 ttl=58 time=35.899 ms
round-trip min/avg/max/stddev = 30.821/33.124/37.181/2.878 ms
```

```
traceroute to example.com (104.20.23.154), 12 hops max, 40 byte packets
 1  192.168.1.1  8.609 ms
 2  198.51.100.17  11.281 ms
 3  198.51.100.149  28.434 ms
 4  203.0.113.178  39.474 ms
 5  *
 6  103.22.201.21  61.408 ms
 7  104.20.23.154  38.096 ms
```

- `time` は、Echo Request と Echo Reply の往復時間。`ttl=58` は応答に残っていた TTL。サーバーはおそらく 64 から始めたので、6 台のルーターを通ってきた。
- traceroute の 1 行が 1 つの TTL で、その TTL のプローブに Time Exceeded を返したルーター。`*` は、時間内に答えがなかったこと。ルーターは ICMP のエラーを制限したり止めたりすることがあり、その次のホップはまた答える。
- macOS と Linux の traceroute は、既定で UDP のプローブを送る（ステップ実行の UDP の場合と同じ）。`traceroute -I` は代わりに ICMP の Echo を使い（Linux では root が要り、traceroute を先に入れる必要があることもある）、Windows の `tracert` はいつもそうする。Wireshark の表示フィルターは `icmp`。

## このページについて

家庭のルーターの NAT は省いたので、PC のプライベートアドレスが経路の最後まで出てくる（NAT のテーマを参照）。traceroute はここではホップごとに 1 回だけ送るが、実際のコマンドは 3 回送って 3 つの時間を表示する。往復時間は描かない（このサイトは遅延を扱わない）。ICMP を制限したり止めたりしているホストやルーターも多いので、答えがないからといって問題があるとは限らない。
